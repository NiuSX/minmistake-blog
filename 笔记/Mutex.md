# Mutex（互斥锁）学习笔记

## 一、什么是 Mutex

**Mutex** 全称 Mutual Exclusion（互斥），是多线程/多进程编程中用于保护共享资源的一种同步机制，防止多个执行单元同时访问同一份数据而导致**竞态条件（race condition）**。

------

## 二、基本原理

核心思想：**任意时刻只允许一个线程持有锁**。

工作流程分三步：

1. **加锁（lock/acquire）**：线程访问共享资源前，先尝试获取锁
2. **访问资源**：加锁成功后，进入"临界区"（critical section）操作数据
3. **解锁（unlock/release）**：操作完成后释放锁，让其他等待的线程有机会获取

> 如果一个线程已持有锁，其他线程再尝试加锁时会被**阻塞（block）**，直到锁被释放。

------

## 三、使用示例（伪代码）

```
mutex.lock()
// 临界区：安全地读写共享变量
shared_counter += 1
mutex.unlock()
```

## 四、各语言中的实现

| 语言            | 对应机制                                |
| --------------- | --------------------------------------- |
| C/C++ (pthread) | `pthread_mutex_t`                       |
| C++11           | `std::mutex`                            |
| Java            | `synchronized` 关键字 / `ReentrantLock` |
| Python          | `threading.Lock()`                      |
| Go              | `sync.Mutex`                            |

------

## 五、需要注意的问题

- **死锁（Deadlock）**：多个线程互相等待对方持有的锁，导致永久阻塞

- **性能开销**：加锁解锁本身有开销，锁粒度太粗会降低并发性能

- 可重入性

  ：

  - 可重入锁：同一线程可重复加锁（如 Java 的 `ReentrantLock`）
  - 非可重入锁：同一线程重复加锁会导致死锁

------

## 六、Mutex 与其他同步机制的区别

### Mutex vs 信号量（Semaphore）

- Mutex：通常只允许**一个**持有者，有"谁加锁谁解锁"的**所有权**概念
- 信号量：可以允许**多个**线程同时访问（计数信号量），没有严格的所有权限制

### Mutex vs 自旋锁（Spinlock）

- Mutex：获取不到锁时线程**休眠**（释放 CPU）
- 自旋锁：**忙等待**（不断轮询），适合锁持有时间很短的场景

## 七、知识速记卡

| 概念   | 一句话记忆                 |
| ------ | -------------------------- |
| Mutex  | 独占锁，一次只让一个线程进 |
| 临界区 | 被锁保护的那段代码         |
| 死锁   | 互相等对方的锁，谁都动不了 |
| 可重入 | 自己拿了锁还能再拿一次     |
| 信号量 | Mutex 的"多人版"           |
| 自旋锁 | 不睡觉，一直问"好了没"     |
